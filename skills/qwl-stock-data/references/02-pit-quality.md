# PIT、质量门禁与完整性

## 60只白名单

合法股票池由 canonical QWL 的 `config/universe.yaml` 与 `config/comparables.yaml` 合并：

```text
12只核心股 + 48只同行股 = 60只
45只A股 + 15只港股
```

扩展数据必须执行：

1. 读取前得到允许代码集合；
2. 市场级结果在内存中过滤；
3. 写盘前逐条 `assert code in allowed`；
4. 写盘后扫描文件名，确认 `found - allowed = empty`。

## PIT可用时间

所有可用于历史决策的事件数据尽量包含：

```text
source_published_at
source_published_on
timestamp_precision
available_on
```

规则：

- 只有日期：下一交易日可用；
- 精确时间且不晚于收盘：当日可用；
- A股15:00后：下一A股交易日；
- 港股16:15后：下一港股交易日；
- 周末和假日：下一对应市场交易日；
- 巨潮午夜占位时间视为日期，不视为凌晨已知；
- 没有可靠发布时间：保留原始记录，但历史因子不可使用；
- 财报期、事件发生日、股东统计截止日不能替代发布时间。

## 财务修订

- 对财务原始内容计算SHA-256，排除派生PIT和汇率字段。
- 相同报告期内容变化时创建新版本，不覆盖旧版本。
- 新观察到的修订以本地首次观测后的交易日生效，禁止回填到旧披露日。
- 修订跟踪启用以前无法重构的版本必须明确标记。

## 行情硬门禁

任一60只股票触发下列条件，市场数据刷新视为失败：

- OHLCV为空；
- 少于60根K线；
- 最新交易日严重落后；
- 缺少开高低收字段；
- 收盘价非正；
- 缺少实时快照；
- 港股任务缺少有效且新鲜的HKD/CNY。

单日绝对涨跌超过35%、少量NaN或轻微供应商延迟为告警，不静默忽略。

## 记录语义校验

- 港股资产负债表：资产约等于负债加权益，误差上限0.5%；
- 一致预期：财年必须在更新时间后0至4年；
- 无EPS、目标价或评级变化的伪修订不得保留；
- 负两融偿还量保留原值并将清洗值置空；
- 北向市值校验 `close × shares ≈ market_cap`；
- 南向同一股票同一日期不得有冲突记录；
- 股东发布时间不得早于观察截止日；
- JSON列表递归检查完全重复记录；
- 行业基准必须使用CNY、完整成分和公司行动中性化；
- 港股财务金额记录原币、单位和CNY换算依据；
- 公司行动周不得生成机械未复权收益标签。

## 快照回放

每次市场刷新冻结：

```text
state/snapshots/<as_of>/<run_id>/
```

快照保存OHLCV、来源、快照、财务、资金流、证据和门禁。验证器逐文件检查：

```text
max(observed_date) <= as_of
```

发现未来行时标记 `invalid_for_replay`，审计记录追加到DuckDB，后续回放强制拒绝。

## 完整性的准确含义

`all_domains_complete=true` 表示：

- 所有预期文件存在；
- 无池外文件；
- JSON可解析；
- 提供商错误为空；
- 已定义语义校验通过；
- 记录完整性扫描通过。
- 需要日频更新的数据域已达到各市场最新应有交易日
- raw 与明确标识的不复权快照、标准化历史与独立 qfq 快照在重叠日期上一致，不能跨口径要求数值相等

它不表示公开市场不存在未发布、禁止抓取或需要商业授权的数据。

历史时序采用追加式合并：只写入新日期，已有日期的供应商修订记录为冲突证据但不覆盖原值

复权序列追加还须检查全部可观察重叠值未变且至少有60个重叠交易日（已有序列不足60日时全部比较），否则不能把新复权基准的尾部拼接到旧序列；这不认证参考窗口之外的历史

旧标准化文件未保存复权元数据且没有明确 qfq 参考时，保留跨口径逐日差异，标记 basis_unverified；股息金额解释、除息日期吻合或拟合系数都不能单独替代复权来源与基准证据

## 周发布历史保护

个人正式版的自动周更不直接修改基础历史文件

- 供应商全量响应在采集工作区完成后按文件压缩归档到本次运行的不可变快照
- 当前周新业务键进入追加版本层
- 已有业务键内容变化视为历史修订，只进入隔离区
- 事件日早于本周开始的首次发现记录视为历史补录，只进入隔离区
- 未来日期和无可靠日期的记录不自动发布
- 自动发布结果必须明确报告 `formal_existing_files_rewritten=0`

隔离记录不代表错误，也不代表已经进入正式历史，必须在用户单独授权并核验证据后才能另行处理
