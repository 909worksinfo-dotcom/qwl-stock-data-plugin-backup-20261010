# 个人正式版周发布契约

## 不变量

- 自动任务只处理固定60只股票和既有市场级数据域
- 插件、插件内Skill和独立Skill由外部SHA-256清单冻结，漂移时在采集前失败
- 正式数据库已有文件的字节内容不因周任务变化
- 每次采集产生的供应商全量文件按运行归档为不可变压缩快照
- 本周新增记录写入追加版本文件，重复记录不重复发布
- 历史修订和旧事件首次补录只进入隔离区
- 当前周授权不能提升为历史授权，也不能触发模型重冻结

## 时间口径

`as_of_date` 表示最近完成交易周的最后目标日期

周开始日为 `as_of_date` 所在自然周的星期一，周结束日为 `as_of_date`

记录先按事件日判断，事件日早于周开始日即视为历史候选，即使本周才被供应商返回也不自动进入正式历史

事件日位于本周且可用日不晚于周结束日时才属于可自动发布的本周新增

## 版本读取

正式数据由冻结基础文件加 `state/published_versions` 中按运行时间排序的追加版本共同组成

读取最新状态时必须叠加版本层，不得只读取基础文件并误报没有更新

`state/quarantine` 不是正式数据层，不得用于模型训练、回测或交易决策

## 授权边界

`PUBLISH_CURRENT_WEEK` 仅代表用户已经授权每周自动增加本周版本

历史修订、历史补录和模型重冻结必须由用户在另一个人工任务中指出具体运行、数据域和处理范围

自动任务和插件均不得生成、推断或复用这类历史授权

## 失败语义

两融逐股日频和市场汇总的本周披露缺口属于非硬性发布前指标，只能以 `margin_pending` 明示并保留失败回执与来源快照；不得填0、补造、复用旧日期冒充本周或称 `all_domains_complete=true`。两融已采到行的字段和数值异常、池外数据、历史改写、两融资格异常，以及其他数据域缺口仍照原规则阻断。此规则不追溯授予旧周自动补数权限

冻结漂移、固定60只边界失败、关键采集失败或正式发布异常都必须返回阻断或失败状态

失败运行不得留下部分发布版本，已完成的供应商快照可作为诊断证据保存在失败运行目录

## 可恢复个人正式版：weekly-contract.20260906

- 唯一写入口仍为 `qwl_weekly_update`，`qwl_publish_weekly_data(publish=true)` 已禁止绕过验收直接发布
- `qwl_weekly_status` 只读返回检查点、缺口、阶段回执与下一次重试时间
- 检查点与采集快照保存在 canonical runtime 的 `state/weekly_jobs/<database-key>/<as_of>/`，不位于 Plugin/Skill 或正式历史文件中
- 同一 runtime 有排他锁，重复调用返回 RUNNING；成功步骤不会因为对话中断或后续缺口而重新执行
- 缺口记录包含 domain、symbol（适用时）、date（适用时）、reason、blocking；不允许把停止披露、不适用、授权源缺失解释为零
- 可恢复失败按1、2、4、8、16分钟退避，累计第6次及以后每小时调度一次；不在工具内部无限重试，达到重试时刻前无采集副作用
- 原生逐股接口按股票拆分，研报按文档拆分；不能拆分的供应商批量请求仍按步骤重试，不能把日频资金流缺口映射成THS多周期快照重采
- 时间窗以北京时间实际日期判断，每个采集步骤及发布验收重新检查；跨周后返回 AUTHORIZATION_REQUIRED_CROSS_WEEK，不再自动补旧周
- JSON 与 Parquet 均合并基础文件和已发布版本后去重；输入重复行不重复发布，冲突键不得覆盖
- 发布前复制形成隔离候选视图，调用原生审计及本周逐交易日/字段检查；发布后再次核验正式层，检查已有文件内容未变
- 旧历史冲突只有明确证实日期全部早于本周且不影响本周输入时作为历史警告保留，历史一致性仍如实为 false；本周冲突、日期不明的冲突或范围污染阻断
- COMPLETE 表示本周正式数据库验收通过，不等于所有历史问题消失或商业数据全部可得
- 新版完成报告另要求独立 `FORMAL_WEEK_ACCEPTED`，复核成功回执、公告窗口及分页、固定60只交易日和正式版本成员SHA；无法证明的来源完整性只能标注限制，不能把失败/伪空窗当作零记录
- 巨潮官方HTTPS的403、非JSON、结构错误为来源阻断，分页截断按退避处理；历史一次性原生HTTP许可不构成以后各周通用授权
- 发布和本周PIT验收后清理器先列出引用与安全副本，仅删除经精确SHA证明冗余的临时文件，不整目录清空 `attempts`
- 意外中断留下未完成的发布目录时安全阻断，不自动删除、回滚或把部分结果当成已完成；正常事务失败只撤销该事务刚创建的版本文件，绝不处理运行前已有文件

## 调度与兼容细节

- 运行契约允许北京时间周六00:00至周日23:59手动启动或续跑，不强制10:00；若另有外部调度，其具体启动时间由调度自行决定，next_retry_at 是允许重试的最早时刻
- 读取状态中的 older_pending_jobs 时，旧周任务只能提示需要单独授权，不得自动续采；NOT_STARTED 的本周任务不由续跑调度新建
- 若旧会话仍持有旧版工具，可用已安装新版中的 scripts/weekly_cli.py 建立新的 stdio MCP 连接；health、status 为只读，update 仍只调用 qwl_weekly_update，不是绕过 MCP 的采集脚本
- weekly_cli.py 必须用 canonical runtime 的 .venv/bin/python -B 运行，status/update 要显式提供 --as-of YYYY-MM-DD；不得改代码或冻结清单来恢复连接
- 原采集器中财报、股息及专项数据“文件存在即缓存”的分支在每周首次任务中强制检查来源；供应商全量返回仅写外部采集工作区和不可变快照，不允许覆盖正式历史
- 采集时间、来源响应哈希、供应商行号不当作业务值修订；原始溯源仍完整保留在快照中，旧正式文件不变
- 旧 schema_version=1/2 已发布内容按原有规则读取；新 schema_version=3 使用数据域业务键去重，本升级不重新解释旧版本或修复旧数据
- 已有月度观测值未变但本周接口错误消失时，仅发布本周采集状态元数据版本，不再次发布旧月份记录

## 项目级恢复和进程隔离

- 检查点沿用同一周、同一数据库及累计attempt，升级不清空旧记录，旧聚合步骤留在legacy_tasks，迁移判断逐项写入item-migration.json
- 旧成功凭证必须有同周回执、不可变快照内的对应数据、结构和日期校验，且与当前业务内容相符；无法验证的项目保持待完成，不伪装成已复用
- 采集器本体不改变供应商算法；只在独立工作区过滤本次股票或研报身份，固定60只外的数据不接收
- 工作进程仅在自身生命周期内设置网络连接/读取超时，不改变系统代理、网络或Python依赖；进程组终止后才读取输出，父进程退出时子进程自行结束
- 原始输出先归档，再校验和准备工作缓存提交；中断提交只允许对预期旧哈希或已接受新哈希续写，其他内容变化安全阻断
- 成功项目以不可变快照成员及SHA-256固定，凭证漂移安全阻断；失败项目不能把上次成功降级，除非本周正式验收明确发现该项目仍有缺口
- 新发现的研报必须通过目录完整性检查，遗漏新文档时本轮不得发布，下一次续跑扩展为新的待完成项目
- 原始供应商输入可能包含历史记录，只保存在工作区与快照；本周正式发布、隔离、重复键及历史字节保护闸门完全保留

## 行情口径与复权重基保护

- 周更市场采集分别取得不复权与明确 qfq 日线，分别存入不可变快照的 ohlcv 与 ohlcv_standardized，记录来源、复权方式及参考末日
- qfq 请求若仅返回 day，不将其伪装为 qfq；参考包含 as_of 之后日期时不可通过裁剪行来消除复权前视风险
- 标准化写入仅接受明确 qfq 输入，复权重基或历史差异默认触发安全阻断，供应商响应留在不可变归档，不改旧正式文件
- 历史差异只有在全部早于本周、本周 qfq 与独立 raw 的 OHLCV 逐日逐字段相等、周前正式收盘与qfq收盘锚点相等且本周无公司行动时，才可保留为隔离警告并原值追加本周新日期，历史一致性仍为 false
- 本周明确除净导致qfq重基时，只有在除净证据的 available_on 不晚于 ex_date、qfq/raw 差异仅出现在除净日前、复权因子稳定且完整本周交易日通过验收时，才可用周前正式收盘作锚点生成 `qfq_chain_v1` 追加版本；仅缩放 OHLC，成交量不缩放，完整锚点、因子、来源SHA和公司行动证据与历史差异一同进入隔离层
- `qfq_chain_v1` 仅是保持收益路径连续的受控派生标准化序列，不冒充供应商原始 qfq，不等于历史修订授权；锚点、当周交易日、公司行动或因子校验任一失败仍阻断
- 旧快照缺少 qfq 时不重采已成功项目来消除告警，记录历史口径待核验；本周逐日对比通过不等于历史一致性完整，不能据此认定模型输入不受影响
- canonical 数据源代码与 Plugin、Skill 一同进入外部冻结校验，自动任务不得修改这些代码或重新生成冻结清单

## 发布契约修复与受控派生输入

- 沪市两融识别精确的SSE五字段形状，文档来源限SSE或保留SSE旧行的EastMoney；ISO与YYYYMMDD仅做比较归一化，五个共享数值必须完全相等且非空，未知字段、单位、PIT变化不予豁免
- SSE工作响应保留原始五字段列表和真实冲突，工作合并不降级已有完整行；EastMoney缓存命中还须满足本周完整字段结构，不能因部分行已到周五就跳过字段补采
- HK公司行动公告按公告ID或完整规范URL、action_type、phase识别，不以通用标题充当唯一键；公告发布时间用于公告证据窗口，不冒充价格调整生效日
- 旧财报依据明确published_at划入历史隔离，不能用report_date回填PIT；content_hash一致不代表available_on、first_seen_at、version_basis一致
- 既有财务版本的内容、哈希、PIT与重复记录保持不动，archive_stock只追加新版本；hk_statement_baseline仅调用只读审计，旧repair_hk_statement_baselines不在周任务链路中
- 行业基准在归一化完成后计算，依赖变化时重新校验派生步骤；正式基础层＋已发布版本＋可追加本周候选先物化成私有视图，不读取quarantine或采用工作区的历史修订
- 维持既有等权、CNY、公司行动生效日中性处理口径，不自动改成含分红再投资的总回报指数；已批准周前正式值作为锚点，旧前缀原样保留，本周每个既有值须独立重算一致
- 公司行动需在生效日当时可用，显式available_on不能被更早公告推算值取代；每个新基准记录保存方法版本、输入SHA、成分、权重政策及锚点，发布验收检查数值和溯源
- 基准真实差异、缺失锚点、成分漂移、来源哈希或PIT异常仍阻断；历史股息修订及模型重冻结仍需另行授权，不因派生指标间接发布

## 人工修复后的检查点复验

- 默认只读调用qwl_weekly_revalidate；在一次性私有副本中运行真实发布前后验收，并先按新受控输入规则重算派生候选，不修改正式数据库、工作缓存或检查点
- 当前仅接受BLOCKED_PUBLICATION检查点；冻结漂移、正式历史漂移、成功凭证损坏和真实当前冲突均保持阻断，复验不是任意BLOCKED状态的解锁器
- 用户另行授权resume=true时还必须传REVALIDATE_AFTER_REPAIR及原检查点SHA，并满足实际周末窗口；先不可变备份原检查点，再更新同一检查点，不清零attempt、不重新启用旧豁免
- 成功凭证及采集快照保留；修复涉及的派生、财务归档、基线审计和归一化步骤重新验证，其他成功逐股项目不重采
- 自动化不得调用恢复模式、删除检查点、修改代码或重冻结来绕过阻断；跨周仍需另行授权
